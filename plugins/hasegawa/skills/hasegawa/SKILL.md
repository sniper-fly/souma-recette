# Hasegawa - Git Commit アシスタント

ステージされていない変更を検出し、適切なコミット粒度の提案からgit commitまでを一貫してアシストする。

## ワークフロー

以下の5ステップを順番に実行する。

### Step 1: 変更状況の把握

以下のコマンドを実行して現在の状態を把握する:

```bash
git status
git diff --stat
git diff --name-only
git log --oneline -10
```

- ステージ済み・未ステージの変更を区別して把握する
- 新規ファイル・変更ファイル・削除ファイルをリストアップする
- 直近のコミット履歴からコミットメッセージのスタイル（言語、形式、prefix等）を把握する

変更がない場合はその旨をユーザーに伝えて終了する。

### Step 2: 機密ファイル検出

`references/sensitive-file-patterns.md` を参照し、ステージ対象のファイルに機密ファイルが含まれていないかチェックする。

1. 既存の `.gitignore` を読み込み、カバー済みパターンを確認する
2. `git status` の出力に含まれるファイルを機密パターンと照合する
3. `.gitignore` でカバーされていないパターンのみを検出対象とする

**Criticalパターンに該当するファイルがある場合:**
- AskUserQuestionで警告し、`.gitignore` への追加を提案する
- ユーザーが同意した場合、`.gitignore` にパターンを追加してからStep 3へ進む

**Warningパターンに該当するファイルがある場合:**
- AskUserQuestionで確認し、除外するか含めるかをユーザーに判断してもらう

該当ファイルがなければそのままStep 3へ進む。

### Step 3: コミット粒度のグルーピング提案

`git diff`（ステージ済みの場合は `git diff --cached`）の内容を分析し、変更を論理的なグループに分類する。

**分類基準:**
- **機能的凝集**: 同じ機能・目的に関する変更をまとめる
- **ディレクトリ近接性**: 同じディレクトリ内の関連する変更をまとめる
- **変更の性質**: リファクタリング、バグ修正、新機能、設定変更など性質ごとに分ける

**提案フォーマット:**

各グループについて以下を提示:
- グループ名（コミットの目的を端的に表す）
- 含まれるファイル一覧
- 推奨コミットメッセージの概要

AskUserQuestionで以下の選択肢を提示:

```yaml
questions:
  - question: "以下のコミット分割案でよろしいですか？"
    options:
      - label: "提案通りに進める"
      - label: "1つのコミットにまとめる"
      - label: "分割を変更したい"
```

「分割を変更したい」が選ばれた場合、具体的な変更内容をヒアリングして再提案する。

### Step 4: コミットメッセージ生成・確認

Step 1で把握した既存コミットの言語・スタイルに合わせてコミットメッセージを生成する。

**メッセージ生成ルール:**
- 既存コミットが日本語ならメッセージも日本語で書く（英語なら英語）
- 既存コミットのprefixパターン（feat:, fix:等）があればそれに従う
- 1行目は変更の要約（50文字以内目安）
- 必要に応じて空行を挟んで詳細を記述
- Co-Authored-by等のtrailerは含めない

AskUserQuestionで生成したメッセージを提示し、確認を求める:

```yaml
questions:
  - question: "以下のコミットメッセージでよろしいですか？\n\n{生成したメッセージ}"
    options:
      - label: "このメッセージで進める"
      - label: "メッセージを修正したい"
```

「修正したい」が選ばれた場合、ユーザーの指示に従ってメッセージを修正する。

### Step 5: git commit実行

確定した内容に基づいてコミットを実行する。

1. `git add` で対象ファイルをステージする（ファイルを個別に指定、`git add .` は使わない）
2. `git commit` でコミットを作成する
3. 複数グループがある場合はグループごとに繰り返す
4. `git log --oneline -5` で結果を確認し、ユーザーに報告する

**注意事項:**
- `git add .` や `git add -A` は使用しない（意図しないファイルの混入を防ぐ）
- コミットメッセージはHEREDOCで渡す
- pre-commit hookが失敗した場合は原因を調査し、修正後に新しいコミットを作成する（--amendは使わない）
