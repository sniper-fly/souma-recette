## フェーズの分け方

以下の基準でセッションをフェーズに分類する:

1. **技術スタックの変更** - 使用ツールやライブラリが変わった場合は新フェーズ
2. **アーキテクチャの転換** - 設計方針が大きく変わった場合は新フェーズ
3. **時間的な断絶** - 数時間以上の空白がある場合は新フェーズの候補
4. **目的の変化** - 「構築」→「テスト」→「改善」などの目的の切り替わり

## ハイライトの抽出基準

以下に該当するエピソードを優先的にハイライトとして抽出する:

1. **エラーからの回復** - 問題が発生し、それをどう解決したか
2. **設計判断の対話** - ユーザーとAIが壁打ちして設計を決めた場面
3. **技術的なピボット** - ある技術から別の技術に方向転換した判断
4. **予期しない発見** - 作業中に見つかった想定外の問題や知見
5. **反復的改善** - テスト→発見→修正のループが明確に見える場面
